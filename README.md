# PlaywrightTests

## Overview
This project contains Playwright-based UI tests using MSTest and targets .NET 9.

## Running the Playwright MSTest Suite

### Prerequisites
- .NET 9 SDK installed
- Playwright browsers installed (run `playwright install` or let the test runner download them)

### Run Tests
From the repository root, run:

    dotnet test

To run a single test project or filter tests, use `dotnet test` options or your IDE's test runner.

Or use the helper script, which builds, installs Chromium, and applies the same suite filters as CI:

    ./Scripts/run-tests.ps1                         # all suites
    ./Scripts/run-tests.ps1 -Suite Smoke -Headed    # watch the browser
    ./Scripts/run-tests.ps1 -Suite Regression -Trace on
    ./Scripts/run-tests.ps1 -Filter "Name~Logo"     # custom filter

| Parameter | Values | Default |
|---|---|---|
| `-Suite` | `All`, `Api`, `Smoke`, `Regression` | `All` |
| `-Headed` | switch | headless |
| `-Trace` | `off`, `on`, `retain-on-failure` | `retain-on-failure` |
| `-Configuration` | `Debug`, `Release` | `Debug` |
| `-NoBuild` | switch | builds first |

The script sets these environment variables, which you can also set yourself when running `dotnet test` directly:

| Variable | Effect |
|---|---|
| `HEADED=1` | Run the browser headed (always headed when a debugger is attached) |
| `PW_TRACE` | `off`, `on`, or `retain-on-failure` (default) |
| `TEST_ARTIFACTS_DIR` | Where screenshots and traces are written (default: `bin/<config>/net9.0/artifacts`) |

### Test Suites
Test classes are named after the feature or page they cover (e.g. `HomePageTests`). Which suite a test runs in is set with `[TestCategory]`, using the constants in `Infrastructure/TestCategories.cs`:

| Category | Purpose | CI job |
|---|---|---|
| `Api` | REST API checks, no browser | API Tests |
| `Smoke` | Fast checks that the site is up and usable | Smoke Tests |
| `Regression` | Deeper UI functional coverage | Regression Tests |

CI and `run-tests.ps1` filter with `TestCategory=<name>`, so a new test class joins a suite just by being tagged; no workflow or script changes are needed:

    [TestClass]
    [TestCategory(TestCategories.Regression)]
    public sealed class CartTests : PlaywrightTestBase

To run a category directly: `dotnet test --filter "TestCategory=Smoke"`.

### Project Structure

| Folder | Contents |
|---|---|
| `Tests/` | Test classes, one per feature or page: `HomePageTests`, `ProductsPageTests`, `CartTests`, `SignUpTests`, `LoginTests`, `SmokeTests`, `ApiTests` |
| `Pages/` | Page objects, one per page: `HomePage`, `ProductsPage` (also search, category and brand listings), `ProductDetailsPage`, `CartPage`, `LoginPage`, `SignupPage`, `AccountStatusPage` |
| `Components/` | Parts that appear on several pages, exposed as properties on the page objects: header, product grid, category/brand sidebar, add-to-cart modal, footer subscription |
| `TestData/` | `TestDataFactory` (unique users and emails) and `AccountApi` (creates and deletes accounts via the REST API) |
| `Infrastructure/` | Suite categories, run-time settings, artifact paths |

Writing tests:
- Tests that need an existing account create one with `AccountApi.CreateUserAsync()` and remove it in a `finally` block with `AccountApi.DeleteUserAsync(user)`. Every account uses a unique `@mailinator.com` address, so parallel runs and reruns don't collide.
- `PlaywrightTestBase` blocks Google ad hosts for every browser test. The site's full-page ads otherwise intercept clicks at random.
- Page objects return `bool` from "is X visible" checks that wait for the element, so tests assert with `Assert.IsTrue(await page.IsXVisibleAsync(), "...")`.

### Viewing Log Output and Screenshots
The tests write diagnostic output to the MSTest `TestContext`. When running `dotnet test`, you can view logs in the console or open the TRX file generated by the runner.

- To see `TestContext.WriteLine` output in the console, run tests with the default logger (the console logger shows written lines when tests fail or when verbose logging is enabled).
- On failure, every browser test saves a full-page screenshot and a Playwright trace to `TEST_ARTIFACTS_DIR/<TestName>/` and attaches them to the TRX results; the paths are written to the test log. In CI they're included in the `test-results-<suite>` workflow artifact.
- Open the most recent trace with `./Scripts/show-trace.ps1` (or pass `-Path <zip>`), or drop the zip onto https://trace.playwright.dev.

### Troubleshooting
- If you do not see `TestContext` output, ensure the base test class exposes a public `TestContext` property so MSTest can populate it.
- Ensure Playwright browsers are installed and the CI agent has access to a display or runs browsers in headless mode.

### Notes
- Tests target .NET 9. Adjust your SDK installation accordingly.
